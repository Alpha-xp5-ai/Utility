Overview

UtilityBelt is a general-purpose helper library for gameplay and UI programmers. It solves the problems that come up in almost every project — knowing whether the player is on mouse, keyboard or gamepad, making UMG menus navigable with a controller, showing the right button prompt, typing out dialogue, easing values, pooling actors — so you can use tested building blocks instead of rewriting them.

  • Input-method detection per local player with events when the player switches between mouse, keyboard and gamepad.
  • Focusable widgets: button, check box, slider, user widget and panel classes that use their Hovered style when focused and raise focus events.
  • Menu stack: hierarchical menus with back/close keys, automatic focus and input-mode / pause / pointer handling.
  • Input prompts: an image widget and a rich-text <input .../> decorator that always show the binding for the active device (Enhanced Input or legacy input).
  • Typewriter text, option selectors, tab lists, a smoothly changing progress bar and stylable subtitle widgets.
  • Gameplay helpers: actor pooling, light flicker component, smooth spring arm, runtime-resizable NavMesh bounds, replicated physics actor, render-target pool.
  • Maths: easing functions, cone/convex/2D geometry helpers, balanced (Halton) random streams and shuffle bags.
  • Editor helpers: an always-visible debug visualisation component and a data-table row picker locked to one table.

Installation

  1. Install UtilityBelt from the launcher into your engine, or copy the UtilityBelt folder into your project's Plugins folder.
  2. For a C++ project, regenerate project files and build the editor target.
  3. Open the project, go to Edit > Plugins, enable UtilityBelt and restart the editor. Enhanced Input and Paper2D are enabled with it.
  4. To use the C++ API, add the module to your .Build.cs: PrivateDependencyModuleNames.Add("UtilityBelt");. The typewriter text widget lives in its own runtime module; add "UtilityBeltTypewriter" as well if your C++ code uses UTypewriterTextWidget (Blueprints need nothing extra).
Verifying the installIn any Blueprint graph, right-click and search for Get Last Input Mode Used (under Belt Game Subsystem). In the UMG palette you should see Focusable Button, Input Image and the other UtilityBelt widgets.

Quick start

Blueprint: react to the player's input method

  1. In a widget or actor Blueprint, add the Belt Game Subsystem node (Game Instance Subsystem getter).
  2. Drag off it and bind to On Input Mode Changed; the event gives you the player index and the new EInputMode (Mouse, Keyboard, Gamepad).
  3. Query the current state at any time with Get Last Input Mode Used or Last Input Was Game Pad.
  4. For prompts, place an UInputImage in a widget, set its Binding Type to Enhanced Input Action and pick an action — it switches between keyboard and gamepad art automatically (requires a UI theme, see UI theme & prompts).

C++

#include "UtilityBelt.h"            // GetBeltGameSubsystem()
#include "BeltEasings.h"

void AMyHUDActor::BeginPlay()
{
    Super::BeginPlay();
    if (UBeltGameSubsystem* GS = GetBeltGameSubsystem(GetWorld()))
    {
        GS->OnInputModeChanged.AddDynamic(this, &AMyHUDActor::HandleInputModeChanged);
        const EInputMode Mode = GS->GetLastInputModeUsed(0);
        UE_LOG(LogTemp, Log, TEXT("Gamepad active: %d"), Mode == EInputMode::Gamepad);
    }
}

// UFUNCTION() void HandleInputModeChanged(int PlayerIndex, EInputMode NewMode);
void AMyHUDActor::HandleInputModeChanged(int PlayerIndex, EInputMode NewMode)
{
    const float Eased = UBeltEasings::EaseAlpha(0.25f, EBeltEaseFunction::EaseOut_Back);
    // ...
}

Menu system

  1. Create a Widget Blueprint, reparent it to UMenuStack and add a Named Slot called MenuContainer where menus appear.
  2. Create one Widget Blueprint per menu level, reparented to UMenuBase; set Initial Focus Widget Name and, if wanted, Input Mode Setting, Mouse Pointer Visibility and Game Pause Setting.
  3. Create the stack and call Push Menu By Class; call Close on a level (or Pop Menu) to go back. Escape and the gamepad face-right button go back by default (Back Keys), the gamepad special-right button closes the stack (Instant Close Keys).

Troubleshooting

SymptomCause and fix
Input Image / rich-text prompts are blankNo UI theme is configured or the Data Tables have no row for the key. Set DefaultUiThemePath in DefaultGame.ini, restart the editor, and make sure the row names match key names (e.g. Gamepad_FaceButton_Bottom).
Prompts work in the editor but not in a packaged buildThe theme is loaded from code, so it is not cooked automatically. Add it as a primary asset in the Asset Manager or reference it from a Primary Asset Label.
The mouse cursor reappears while using a gamepadSet Game Viewport Client Class to BeltGameViewportClientBase and keep Hide Mouse When Gamepad Used enabled.
A dotted outline appears around focused buttonsSet Project Settings > User Interface > Render Focus Rule to Never; the focusable widgets use their Hovered style instead.
<input eaction="..."/> shows nothingThe action is looked up by name in Directories to search for Enhanced Input Actions; add the folder that contains the Input Action asset.
Menu levels do not appear inside the stackThe Menu Stack Blueprint needs a Named Slot (or other content widget) called MenuContainer, and Embed In Parent Container must be enabled on the level.
Dynamic NavMesh volume changes have no effectSet the RecastNavMesh Runtime Generation to Dynamic in Project Settings > Navigation Mesh.
